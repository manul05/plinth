# K4 Rule-pack format (`pk-rulepack/1.0`)

**Status:** normative for Plinth 0.1 (2026-10-31). **Vectors:** `contracts/test-vectors/k4/` (35). **Schemas:** `pk-rulepack.pack-source`, `pk-rulepack.manifest`, `pk-rulepack.rules`, `pk-rulepack.tests`. **API:** subpath `plinth-kit/rulepack`; compiler in `packages/ts/src/repo-tools/` (Node only, not shipped).

**Purpose:** every rule carries source, version and effective date, has tests, and changes as data with history.

## 1. Layout
- Sources (authored, reviewed): `rules/<pack-id>/pack.yaml`, `rules.yaml`, `tests.yaml`. The four 0.1 packs were authored in Stage 3: `pk.secrets.global` (12 rules), `pk.secrets.india` (8), `pk.pii.india` (7), `pk.untrusted-text` (8); 70 tests.
- Compiled (committed, consumed by products and other languages): `packs/<pack-id>/pack.json`, `rules.json`, `tests.json`. Each file's bytes are exactly `canonicalize(value)` (UTF-8, no trailing newline). `pack.json` = pack.yaml value plus `files: [{path:"rules.json", sha256: digest(rules)}, {path:"tests.json", sha256: digest(tests)}]` in that order.
- TS products use the generated module `packages/ts/src/packs/builtin.ts` (`BUILTIN_PACKS`), generated by the same compiler from the same values.
- Products consume compiled JSON only, never YAML.

## 2. YAML safe subset (`yamlToValue(text, fileName)`, repo-tools)
Parse with `yaml` 2.9.1: `parseDocument(text, {version:'1.2', schema:'core', uniqueKeys:true, merge:false, prettyErrors:false})`.
1. Errors: code `DUPLICATE_KEY` → `PK_RULEPACK_YAML_DUPLICATE_KEY`; `MULTIPLE_DOCS` → `PK_RULEPACK_YAML_MULTI_DOC`; any other → `PK_RULEPACK_YAML_SYNTAX`.
2. Walk with `visit`: an `Alias`, or any node with `anchor` → `PK_RULEPACK_YAML_ANCHOR`; any node with `tag` set → `PK_RULEPACK_YAML_TAG`.
3. Every scalar of type `PLAIN`: if its value is a string, its `source` must not match `^[0-9]{4}-[0-9]{2}-[0-9]{2}` nor `^(y|Y|yes|Yes|YES|n|N|no|No|NO|on|On|ON|off|Off|OFF|true|True|TRUE|false|False|FALSE|null|Null|NULL|~)$`; if its value is not a string, its `source` must match `^(0|-?[1-9][0-9]*)$` or be exactly `true` or `false`. Otherwise → `PK_RULEPACK_YAML_AMBIGUOUS_SCALAR` (this refuses `3.5`, `010`, `0x1F`, `.inf`, `yes`, empty values).
4. `value = doc.toJS()`; then `canonicalize(value)` must succeed (its PK_JCS_* error is thrown otherwise).

## 3. Compile algorithm (`compilePacks({rulesDir, packsDir, builtinPath, check})`)
For each pack directory in ascending name order:
1. Read the three YAML files with §2.
2. Validate with Ajv 2020 (strict) against `pk-rulepack.pack-source`, `pk-rulepack.rules`, `pk-rulepack.tests` → `PK_RULEPACK_SCHEMA` (detail = file + first Ajv error `instancePath message`). `rules.pack_id` and `tests.pack_id` MUST equal `pack.id` → `PK_RULEPACK_SCHEMA`.
3. `kind` must be `secret-detection`, `pii-detection` or `untrusted-text` → else `PK_RULEPACK_KIND_UNSUPPORTED`; each rule body must be the body type of that kind (secret body has `provider`, PII body has `pii_type`, untrusted body has `class`) → else `PK_RULEPACK_SCHEMA`.
4. Duplicate (id, rev) → `PK_RULEPACK_DUPLICATE_REV`. Two revisions of one id whose half-open windows `[effective_from, effective_until or 9999-12-31)` intersect → `PK_RULEPACK_OVERLAP`.
5. Every `regex` and every `allow` entry passes `lintRegex` (§5) (allow entries with flags `""`). Every `pair_with.rules` entry names a rule id in the same pack → else `PK_RULEPACK_UNKNOWN_PAIR_RULE`.
6. Every rule id has ≥ 1 test with `expect: "match"` and ≥ 1 with `expect: "no_match"` → else `PK_RULEPACK_TESTS_MISSING`.
7. Run every test (§6) → first failure `PK_RULEPACK_TEST_FAILED` (detail = rule id and test index).
8. Build manifest (§1) and write `packs/<id>/*.json` and `builtin.ts`. With `check: true` write nothing; compare the would-be bytes with the files on disk and exit 1 listing differing paths.

## 4. "As of" selection
- `selectAsOf(rules, ruleId, date)`: candidates = rules with that id, status ≠ `withdrawn`, `effective_from ≤ date` and (no `effective_until` or `date < effective_until`) — string comparison of `YYYY-MM-DD`. 0 → null; 1 → it; more → `PK_RULEPACK_OVERLAP`. The date is the **event date**, not today.
- `localDate(ts, tz)`: `Asia/Kolkata` → date of `ms + 19 800 000` in UTC; `UTC` → date of ms; anything else → `PK_RULEPACK_TZ_UNSUPPORTED`.
- `activeRules(pack, date)` = rules (pack order) whose status is `experimental` or `stable` and for which `selectAsOf(pack.rules, rule.id, date) === rule`.

## 5. Portable regex dialect (`lintRegex(pattern, flags)`, repo-tools)
1. flags ⊆ {i, m, s}, no repeats → else `PK_RULEPACK_REGEX_DIALECT`.
2. Scan left to right. After `\` the next character must be one of `b n r t \ . - / [ ] ( ) { } * + ? | ^ $`, or `x` followed by exactly 2 hex digits → else `PK_RULEPACK_REGEX_DIALECT` (so `\d \w \s \p{…} \1 \k<…> \u…` are refused). Every `(?` must be followed by `:` → else `PK_RULEPACK_REGEX_DIALECT` (refuses lookaround, named groups, inline flags).
3. `new RegExp(pattern, "dgu" + flags)` must not throw → else `PK_RULEPACK_REGEX_INVALID`.
4. `safe-regex2` 5.1.2 default export `safeRegex(pattern)` must return true → else `PK_RULEPACK_REGEX_UNSAFE` (nested quantifiers, star height > 1).
Why: the same patterns must later run in .NET (`RegexOptions.NonBacktracking`) and the JVM.

## 6. Rule tests
Test text = `input_parts.join("")` (parts keep secret-like strings out of the repo as whole tokens). Run `scan(text, [loadPack(compiled)], {date: rule.effective_from})` (no installation secret). Pass = (a finding with `rule_id === test.rule_id` exists) equals (`expect === "match"`).

## 7. Runtime loading
`loadPack(compiled)`: `manifest.spec === "pk-rulepack/1.0"` and `min_engine === "pk-rulepack/1.0"` → else `PK_SPEC_UNSUPPORTED`; kind in the three supported → else `PK_RULEPACK_KIND_UNSUPPORTED`; `digest(rules)` equals the `rules.json` entry and `digest(tests)` the `tests.json` entry → else `PK_RULEPACK_FILE_HASH_MISMATCH`. Returns `{manifest, rules: rules.rules}`. Loading does not re-run lint or tests (done at compile time; integrity is the digest check plus the release `SHA256SUMS`).

## 8. Not in 0.1
Signed runtime pack updates (`pk.rulepack` envelopes, anti-rollback) and kinds other than the three above; gitleaks TOML exporter (comes with LeakSweep, 0.3).
